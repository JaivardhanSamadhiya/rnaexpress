# Deferred full supplied-checkpoint replay

This finite source layer accepts an already-admitted prepared-pool object and immutable BoundPlan, raw supplied campaign-birth/completion JSON, and exactly 63 supplied records. Each record has exactly `task_key`, `birth_raw`, `checkpoint_raw`, `completion_raw`. It reads no files, loads no runtime, invokes no provider or optimizer and has no CLI. The public API is `verify_campaign(np, prepared, plan, campaign_birth_raw, records, campaign_complete_raw)`. Its resource/proof/pool dependencies are fixed; caller-injected callbacks exist only in a private invented-test helper. The default original loader guard is used before work and actions. Existing scoped resource-calibration machinery can cover that guard and the pre-existing arithmetic/engine aliases; this layer adds no resource override or new directly imported `require_resources` alias.

Before numerical replay, exact full inherited metadata and pool rows/order, immutable prefit/runtime/identity declarations and every actual array/label/pair/scaling binding are checked with the frozen engine pool hasher. Missing, extra, duplicate, malformed or nonfinite records stop. Every raw birth, checkpoint and completion hash is chained to the supplied campaign birth, source pool, prefit commit, fixed task/configuration, complete target IDs/order/shape, and expected named optimizer dimensions. The full campaign completion must list exactly all 63 checkpoint completion hashes, 54 inner and nine outer records, and the recorded 84 unit invocations. These are logical supplied-record checks; they do not independently prove physical write timing, durable birth-before-fit, actual native optimizer execution or Git/input/runtime admission. Those remain obligations of the separately verified controller and lifecycle.

Each supplied checkpoint runs the existing separate scalar/scaling/objective/gradient and exact full-shape canonical arithmetic primitive. Its original strictly-below-1e-9 bounds remain unchanged; exact canonical saved scores are never replaced by tolerance-band choices. Source/target pool hashes are recomputed again after arithmetic to reject mutation. No new convergence or biological threshold is introduced. Maximum existing arithmetic differences are reported. No refit, feature, grid, loss, split, coefficient or label changes occur.

The nine outer configurations are independently reselected from the 54 verified inner checkpoints. The new selector does not call the production selection helper. It independently computes lexical-ID exact-score choices, both directional regrets, paired menu/component/cell means and concatenated two-fold source OOF metrics. The original within-1e-12, fixed three-configuration order is used only for configuration selection. Unequal folds are not averaged equally. All source OOF IDs/order, including unmatched menus, are mandatory; only the fixed full paired menus enter the criterion. Only outer-training effects enter selection, and the API supplies no held-truth argument. All six inner predecessor hashes, source identity, full configuration-metrics digest and selected configuration must exactly reproduce each saved outer selection receipt.

Canonical outer prediction records are returned in the existing evaluation adapter's three-field schema only after all 63 arithmetic and nine source-selection checks pass. A failure at the final checkpoint returns no partial outer records. Evaluation and the fixed joint-only known-cell gate remain separate steps; this verifier does not run them or claim success, novelty, an unseen cell, independent confirmation or optimizer optimality.

Tests use small invented metadata and raw JSON records, with private pool/arithmetic stubs to exercise all 63/84 logical paths. Separate source-only selector tests compare against the frozen reference on unequal folds and exact ties. These stubs are expressly not 63 numerical replays or a native-runtime certificate. No actual checkpoint, project metadata/effect/array, guard probe, provider, worker or native scientific package is opened or invoked during preparation. Actual 13,781-row pool hashes, the full 63 native arithmetic calls, independent current-runtime/origin proof, committed stage/source/input admissions and lifecycle durability remain unexecuted prerequisites. A source freeze provides no execution or FIT permission.
