## Fixed roster and nine source pools

`contracts.task_roster()` delegates to the frozen reference `checkpoint_roster`: pooled, independent and joint_shrink10; three outer folds; two inner folds and three fixed lambda configs per outer fold. There are54 inner arm checkpoints and9 source-selected outer arm checkpoints,63 filesets total. Independent invokes two102-coordinate units, pooled one102-coordinate unit and joint one204-coordinate unit. The fixed total is84 invocations,72 inner and12 outer. There are exactly nine shared source pools: six inner and three outer. Every arm and lambda reuses the same pool identity for its corresponding outer/inner split.

A future campaign prefit must use the exact schema enforced by `validate_prefit`: frozen counts/configs/arms, one thread, no resource exception, all13781 original row IDs in admitted global order with inherited folds, the admitted runtime hash, metadata/feature/parsed-label/source-manifest certificates and nine source-pool declarations. Each pool binds complete training and full validation IDs/order, parsed source effects, features, metadata, original pair roster, new hierarchical weights, common scaling, and corresponding complete validation metadata/feature/effect hashes. Pair counts, same-both-cell/full-menu certificates and zero gene/component/original-allele contradictions are required. Expected ID masks are independently reconstructed from both-cell inherited fold unions. Any changed order, partial target or altered source pool stops.

These declarations are not independent scientific certificates produced by this infrastructure. The future guarded loader must actually establish both-cell/component/gene/allele/menu identity, common feature parity, original label parsing, pair roster/weights/scaling and actual source hashes. The original reference component purge must have no contradictions; the lifecycle planner does not silently invent a new purge. Primary paired2408-menu selection and all-row secondary reporting remain as frozen; this layer does not compute or change either population.

`bind_plan(relative_prefit_path, prefit_bytes, commit, committed_reader, current_runtime_hash)` checks safe relative aliases and exact equality with an injected exact-commit reader before parsing, then requires the current supplied runtime hash to match prefit. The future root must separately review/certify that reader's Git implementation and actual runtime-origin verifier. The module itself runs no Git command and cannot turn a caller-provided digest into a native runtime proof. Bound plans retain immutable prefit bytes; their accessors return copies.

## Birth before optimization and exclusive output lifecycle

`Campaign(new_directory, bound_plan)` requires a previously absent directory and writes a durable exclusive `campaign_birth.json`. `write_checkpoint(key, callback, selection=None)` exclusively writes and fsyncs the complete checkpoint birth identity **before** invoking the callback. It delegates required source fields to the frozen reference `birth_identity`, then adds full validation identity/shape, source-pool digest, committed-prefit identity and source-only outer-selection binding. Source IDs/order, parsed effects, feature values, pair roster, weights, common scale, configuration, runtime and prefit therefore precede optimizer invocation in the birth record. Configs for inner fits come from the fixed roster, not callback input.

Outer fits require a supplied receipt declaring the original concatenated paired OOF/equal-cell/component/context/direction criterion, one selected fixed lambda, source-only and paired-only flags, exact source-training ID digest, common runtime/prefit, configuration-metrics digest and all six completed same-arm/same-outer inner checkpoint digests. The complete receipt is stored in outer birth, and later replay revalidates those six exact bindings. This binds a supplied source-only choice; it does not independently recompute regret or prove the receipt's arithmetic. Future independent selection replay is mandatory before any scientific conclusion.

The callback receives deep copies of task and birth metadata plus `UnitCalls`. A reviewed future adapter must wrap **each actual** native `minimize` call through `units.invoke(name, dimension, callable, ...)`: pooled102, CAD102 then Neuro-2a102 for independent, joint204. This counts supplied callable invocations and rejects missing, duplicate, wrong-order, wrong-dimension or failed units. It is not a profiler proving that an arbitrary callable is SciPy. That proof belongs to the future frozen adapter/runtime/native profile. Invented tests invoke only trivial standard-library callbacks.

Returned models must exactly match the committed numerical companion's schema: same arm/config, original102 columns/scorer/zero mean/optimizer options, source counts, pre-birth common-scaling digest, supported finite coefficient vectors, fixed number of heads, successful finite optimizer summaries and their appropriate pooled or half-sum objective. Extra heads/fields are rejected. Prediction metadata must declare full float64/C/102 scoring, and scores must be finite with exactly every expected validation ID in its original full-matrix order. The writer checks those declarations and values but cannot itself certify that a callback used the native full-shape scorer; the future adapter/native and independent score replay must establish that fact.

After verifying unchanged birth bytes, the writer exclusively saves the model/prediction object and then its completion receipt containing exact birth/model SHA values and counted invocations. No pickle or arbitrary-object decoder is used. No output is replaced, resumed or overwritten. A callback or validation failure leaves birth/partial evidence plus an exclusive failure record; that campaign object and directory cannot resume. JSON duplicate keys and nonfinite tokens are rejected on read. These are accidental-overwrite protections and auditable hash bindings, not filesystem access-control claims; later committed result inventories and independent replay remain required.

`check_saved` reconstructs full birth identity, model/prediction/schema/input/selection bindings and invocation roster against actual saved bytes. `finish` requires exactly all63 complete birth/model/receipt filesets, no failures/unknown files,84 successful recorded invocations and unchanged campaign birth before writing a distinct completion record. This status explicitly means **lifecycle complete**, never numerical/selector replay or gate PASS.
