# Prospective fail-closed writer correction

Prepared before any root commit or project run of this infrastructure. Independent source review identified two lifecycle control gaps: the original checkpoint birth write/fsync occurred outside its internal failure handler, and the run-birth digest was checked at completion/saved-checkpoint verification rather than before every new callback. The complete original50-pin manifest, source, protocol,15-test receipt and logs are retained byte for byte.

The new `writer_v2.Campaign` subclasses the original writer without modifying it. The entire original `write_checkpoint` call is enclosed in an outer `BaseException` handler. Every failed checkpoint attempt now sets `failed=True`, including invalid selection/unknown key, partial birth write, fsync, original model/callback validation and failure-evidence write errors. Before delegating, the wrapper requires the actual `campaign_birth.json` digest to equal its creation digest. A mismatch stops before checkpoint birth or numerical callback. Later keys cannot proceed on a poisoned object, and an existing run directory cannot be reconstructed/resumed.

Original partial outputs and any original failure record remain untouched. A separate exclusive `campaign_failure_v2.json` attempts to record pre-birth/partial-write failures too. If the same I/O condition prevents that record, the campaign is still poisoned; the original exception is re-raised with an added note describing the evidence-write failure. No automatic retry, overwrite, resume, algorithm, weight, fold, configuration, resource threshold or gate change is introduced.

The invented v2 tests cover actual partial-byte birth fixtures, injected checkpoint-birth fsync failure, changed campaign birth, failed evidence logging, invalid selection/unknown key, original callback failure and a valid complete63-checkpoint/84-call fixture. They show a different key cannot invoke a callback after each failure. Plan/source tests from v1 also rerun unchanged. These are standard-library lifecycle tests only, not native optimization, a project campaign or biological validation.

All future adapters must import `writer_v2.Campaign`. The original `writer.Campaign` is preserved historical preparation and is not the prospective execution class. Source-only preparation remains distinct from real input/runtime/FIT admission, numerical/selector replay and the frozen gates; all original3GiB/1GiB/one-thread requirements remain.
