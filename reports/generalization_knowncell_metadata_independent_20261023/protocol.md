# Pure independent supplied-metadata verifier

This additive source implements a pure verify_bundle(value) API. It accepts
already supplied JSON bytes or a JSON dictionary, opens no path, calls no Git,
existing project parser, loader, reference contract builder, probe, provider, worker or scientific
package, and fits nothing. The separately owned independent-metadata invocation,
its source/admission/controller, actual input acquisition, resource supervision
and committed actual result remain separate prerequisites. No execution or
authorization record is created by this preparation.

Definitions come from the frozen design/specification and existing metadata
contract, read as source text only. Implementation imports none of those
builders. It reconstructs its own context and component maps, full-menu
signatures, exact cross-cell pairs, unmatched menus and global-index partitions.
Both held cells define component and exact original parent/mutant exclusions.
Gene names use the declared strip-and-uppercase comparison solely for overlap
checks. Contradictions stop; no additional purge, gene repair, normalization of
stored rows, favorable intersection or candidate filtering occurs. Every source
and target menu remains complete; every original row is held out exactly once,
and every outer source row is validated exactly once across its two inner folds.

The public interface fixes 13,781 rows, CAD6,889/Neuro-2a6,892,187 components,
three inherited folds,2,408 exact paired menus/13,760 rows/4,816 contexts/9,632
directional decisions, and nine unmatched contexts/21 rows. The exact original
ID/order hash d5a603fb35e25af47d60cc10ac41ae18458c094b855de29561cdecb5edaa0ce2
is mandatory. All ten original metadata fields remain exact. Metadata rows may
contain no outcome/score columns. Source metadata hash and saved contract are
compared against the independently reconstructed versions. Contract hash uses
sorted compact ASCII JSON plus a trailing newline. The original metadata hash
uses the fixed column-ordered list of rows with compact ASCII JSON, without a
newline; original IDs use the literal pipe-joined original-order hash.

Supplied bytes are bounded to64MiB, duplicate JSON keys and nonfinite values
reject, and dictionaries must be plain finite JSON data. No input dictionary
is mutated. Actual byte SHA is reported only when bytes were supplied;
dictionary input has a separately named canonical JSON hash, never an invented
file-byte SHA. Calibrated resource annotations remain outside metadata rows and
contracts and do not change the scientific reconstruction. The verifier does
not certify those resource annotations or actual ownership/approval.

Invented tests use a hand-defined17-row, three-component fixture with3 exact
paired menus and two unequal unmatched menus. Explicit global-index masks are
written independently in the fixture, covering all three outer and six inner
partitions. Private helper count parameters exist for these tests only; the
public API has no counts or original-ID-hash override and rejects that fixture
as actual project input. No full-size positive actual-data test has run here.

Completeness is bounded: a supplied bundle permits independent ID/order-pin,
count, menu, purge, mask and contract verification. It does not independently
prove the source CSV derivation or author lineage of each field. It validates
original_core_rows structurally but cannot verify their actual CSV alignment
without the original source records. Likewise it cannot reconstruct the
non-Mikl full26,258-ID roster from Mikl-only supplied rows. The report marks
these limits false explicitly. The future owned controller must bind committed
original acquisition bytes/receipt/admission and the new actual verifier result;
any stronger source-derivation claim needs further independent evidence.

Only a successful future public full-size call returns
PASS_INDEPENDENT_SUPPLIED_METADATA_CONTRACT_NOT_IO_OR_FIT_ADMISSION. Source
preparation and invented tests are not actual metadata PASS, array/label/FIT
admission, a committed prefit, checkpoint replay, evaluation or generalization.
Array admission must wait for the separately supervised independent invocation
and committed result. All old sources, resource policies and sealed results are
preserved.

The additional public API source_verify.verify_bundle_and_core(value,source)
accepts the same bundle plus caller-supplied CORE text or a caller-owned text
stream. Its independent csv.DictReader implementation requires a unique header
containing the ten metadata fields, exact record widths, unique nonempty IDs
across all26,258 records and exactly one physical record per line. Blank lines,
including trailing blanks, and quoted multiline records reject. Only Mikl
records retain metadata; only their inherited-fold tokens receive bounded
Decimal conversion to0/1/2. Unused outcome columns are CSV tokens, never numeric
effects. The complete source is traversed, including non-Mikl records, to rebuild
full ID order, source positions, source-row count and selected metadata. It
compares all12 parsed metadata fields exactly with the acquisition bundle, then
independently reconstructs every menu, split and contract as above.

This supplied-CORE API can verify source-field derivation, source positions and
the full-core ID roster against the exact stream supplied. It does not open or
close that stream or claim a raw-byte SHA for normalized text. The future owned
controller must supply its UTF8-sig text stream from an independently hash-guarded
open of the exact admitted CORE bytes and bind that raw read/Git/authorization
receipt. Success status is
PASS_INDEPENDENT_SUPPLIED_CORE_AND_METADATA_CONTRACT_NOT_IO_OR_FIT_ADMISSION.
Author biological lineage remains unverified by this parser; accurate copying
of admitted source annotations is a narrower claim. Actual data verification
has not run in this preparation.
