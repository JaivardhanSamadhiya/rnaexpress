# Prepared execution and integrity controls

The final three-track protocol supersedes the earlier uncompressed feasibility proposal without changing catalog inclusion, motif score formula or four pool definitions. Four independent421×64 Gaussian matrices compress the pools to256 columns. The exact same arrays serve raw and accessible features. Raw scoring uses one worker and OPENBLAS_NUM_THREADS=OMP_NUM_THREADS=1 while larger jobs run. Each allele's421×window scan is transient; caches retain float64 projected global summaries and only fixed requested edit-position summaries. Model blocks are cast float32 after mutant-minus-parent subtraction. No full collection of motif-window scans is kept in RAM or on disk.

Every completed raw/access allele NPZ has an immutable creation sidecar binding its byte SHA256, sequence SHA256, ordered edit-request SHA256, mode and production-manifest SHA256. Replay checks this sidecar before accepting finite arrays or constructing any new final index. Missing sidecars, changed payloads, changed requests and orphan pending files are preserved and rejected. Creation publishes a validated pending NPZ before writing its receipt; a crash in that short publication gap requires an explicit separate audit rather than treating an orphan as valid. Full cache indices additionally hash creation sidecars. Access reads the certified source structure cache, binds each source NPZ hash into its own cache and rechecks it before assembly and replay.

The strict gate imports the committed next-generation shared_bootstrap helper. One underlying exponential weight per biological component is reused across every assay containing it, with within-assay weight normalization and equal assay averaging. The numeric thresholds remain unchanged. The helper itself is pinned by the separate RBP freeze.

The first seven-test receipt is preserved. The final scoped test receipt includes an additional synthetic cache corruption/replay check and records all current source hashes; the production freeze checks those hashes. Scoring, parser, projection and candidate-request tests use synthetic inputs only. The command to prepare this receipt is `python -u -m src.generalization_rbp_20261007.tests`; it does not produce project features or fit models.

Root reviews the code, creates the separate production certificate, commits it and explicitly starts raw production. Access waits for structure-production PASS. Assembly requires both completed modes and preserves exact original row/allele identity. Root then creates and commits the separate prefit certificate before starting120 comparative checkpoints. Independent verification replays every saved candidate score and extreme choice/regret, checks every feature row against caches, and separately scores a deterministic example from each assay with the independent pool API.

No original catalog file redistribution bundle is planned. The official archive, extracted evidence manifest and normalized matrices are retained internally with source URLs and license limitations. This preparation provides no positive localization result or independent biological confirmation.
