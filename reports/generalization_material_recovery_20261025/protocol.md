Fresh software scanning produced D: stream-read and failure-log-open errors.
A disk153 retry at18:01:09 local maps to D:'s USB Disk1. The lifetime toy's
journal stopped one second later without terminal evidence; neither this
timing nor the old bitmap warning establishes the earlier FIT's cause.

One copy-only pass may stage at most1 GiB under the existing private C: recovery
folder, reserving at least2 GiB free C: space, within600 seconds. It selects the
701-pin source closure, admitted inputs, all saved checkpoint declarations,
33 protected user files, unchanged7998 scientific software files, fixed current
42 bundled native files and current bundled stdlib source. No CORE reread,
closed outcome namespace, unknown dataset, numerical package import, model
fit, source deletion/repair or global configuration change is included.

Every destination is new and confined to the private recovery directory.
Each file is streamed once, checked against the fixed expected digest, fsynced
and rehashed on C:. A source error, changing file, cap/reserve violation or
deadline aborts without retry, keeping verified prefixes and a C: failure log
that identifies the current source path. No old source file is repaired or
overwritten. The copy is neither a full-drive backup nor current scientific
runtime admission. Private copied user contents are not added to Git.
