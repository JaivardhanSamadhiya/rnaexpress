# Outcome-blind original-insert similarity robustness preparation

7 October 2026. This new namespace prepares a possible stricter cross-cell test. It does not alter any existing frozen split, feature, fit, gate or verdict. No supervised fit is authorized by this preparation.

The sole primary sequence criterion is **global unit-cost Levenshtein distance <=30 between complete original 150-nt biological inserts**. It was explicitly fixed by the root investigator before any project similarity graph counts. Each insertion, deletion or substitution costs one; strings are compared in their recorded expressed orientation, with no preprocessing. At this equal length, the normalized edit similarity is >=0.80. This is an operational near-sequence criterion, not 80% ungapped identity, local-overlap identity, reverse-complement similarity, evolutionary homology, gene paralogy or a claim to exclude every shared regulatory motif. No threshold sensitivity grid, outcome-based cutoff choice or favorable subgroup selection is included.

The only input is the previously admitted Mikl metadata roster: intervention, original parent and mutant sequence, biological component, gene, known cell/endpoint and inherited three gene folds. The metadata loader reads no measured_delta column. All unique original parent/mutant alleles are deduplicated; any close pair joins its owning genes. Exact alleles owned by multiple genes also join them. Whole-gene connected components include transitive paths across every admitted original allele and both cells. Consequently two genes in one component need not themselves have distance <=30. This is conservative grouping, and target sequence metadata informs exclusion only, never fitted features or hyperparameters.

Exact all-pair distances use the existing MIT-licensed RapidFuzz3.14.1 native runtime, unit weights, processor=None, cutoff30, one worker and int16 output. The cutoff returns31 for distances above30. Blocks of64 queries compare against every later allele, and the strict upper triangle is processed exactly once. There is no heuristic prefilter, approximate nearest-neighbor retrieval or dense persistent distance matrix. The maximum temporary distance matrix is64x9,318x2=1,192,704bytes, excluding the small runtime/metadata overhead. Native package and compiled scorer/process file hashes, source metadata, allele ownership and graph output hashes are recorded. Independent Wagner-Fischer dynamic programming validates synthetic scalar/matrix cutoff behavior, symmetric distances, indels, exact matches, threshold boundaries and a shifted string whose ungapped disagreement differs strongly from global edit distance.

Future supervised use would retain **all original target menus, rows, directions and folds**. For each source-cell to target-cell fold, start with the already reviewed source-only, target-gene-fold-excluded masks. Apply the original global biological-component/exact-allele purge, then remove every training component sharing the target's globally defined similarity family. Each source-only inner fold repeats the same additional global family purge. The graph is never recomputed from the narrower training subset. Empty or severely reduced source/inner support is a feasibility finding; no fold, menu, threshold or similarity link is removed to manufacture viability. Counts of rows, contexts, genes and families before/after each purge are recorded without outcome access.

The graph receipt contains direct gene-edge witnesses (sequence SHA, exact edit distance, Hamming disagreement, distinct4-mer counts) and transitive membership. Low-complexity matches may join biologically unrelated genes; these descriptive checks expose bridges without removing them. A passing future result would support transfer under this stated full-insert similarity exclusion, not absence of biological homology. Conversely, no close cross-gene edges would show only that this specific150-nt/30-edit rule adds no exclusion to the original gene test. It would not certify homology independence or lack of longer-transcript, local-overlap or motif leakage.

Prior art motivates this control. [mRNABench](https://pmc.ncbi.nlm.nih.gov/articles/PMC12265608/) describes leakage remaining under chromosome holdout and uses paralog-derived, transitive gene groups; its evolutionary grouping is distinct from this insert-only graph. [Author benchmark code](https://github.com/morrislab/mRNABench) already supplies biologically informed split strategies, so similarity-aware exclusion itself is not a new algorithm. [RapidFuzz distance documentation](https://rapidfuzz.github.io/RapidFuzz/Usage/distance/Levenshtein.html) specifies unit-edit and cutoff semantics; [matrix documentation](https://rapidfuzz.github.io/RapidFuzz/Usage/process.html) specifies native scorers, integer distance outputs and worker controls. Those live docs currently label3.14.6; the executed3.14.1 package and its local source/compiled bytes are pinned independently. [Version3.14.1 author source](https://github.com/rapidfuzz/RapidFuzz/tree/v3.14.1) is the version reference. No installation, paid service, new biological dataset, count file, reserved outcome or model result is used.

Any later experiment requires independent code review, a separately committed prefit manifest, fixed feature/control/gate choices and root authorization before fitting. The existing seven feature arrays and source-only penalty selection are only a possible future reuse; no new model is prepared or trained by this namespace. Repeatedly exposed development data cannot serve as independent confirmation.
