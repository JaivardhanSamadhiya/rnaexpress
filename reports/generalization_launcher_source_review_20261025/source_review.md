The inspected source implements a1,800-second original total-stage deadline, not a900-second launcher deadline. The paged supervisor forwards that start into the monitor and all terminal resource checks. WinJob sets only active-process/process-memory/job-memory/KILL_ON_JOB_CLOSE flags; it does not set a per-process/job CPU-time limit in this implementation. This limited source survey cannot rule out external host/inherited-job, OS, user, crash or storage causes, and does not identify any of them as responsible.

The supervisor owns the exact job handle. Job.close closes it and the configured KILL_ON_JOB_CLOSE policy is intended to stop remaining owned children when that handle closes. The child is created suspended, assigned/verified in the exact owned job, then resumed. The headless facade substitutes DETACHED_PROCESS for CREATE_NO_WINDOW to avoid the earlier console helper; it does not request BREAKAWAY_FROM_JOB, change host hierarchy limits or make the supervisor itself persistent. Consequently disappearance of both owner and worker is consistent with several lifecycle paths and does not itself identify the original trigger. Removing kill-on-close or silently breaking away would weaken the approved owned-job boundary and is not proposed.
