# Proposed resource-only calibration adapter

This source is **proposed and not authorized for execution**. It neither creates an authorization file nor records invented human approval. No production context, actual resource probe, scientific import, project input or worker is run during preparation. Root owns the separate plan, common authorization/owner contracts, hard-Job supervisor, actual-stage entrypoints, execution manifest and any later human approval. The present adapter does not freeze a manifest or stage commits.

The public API is `calibrated(stage, manifest_sha, owner_evidence)` as a context manager. Stages are exactly metadata, array, labels, prefit, fit, replay and evaluation; this enum does not mean all stage controllers or admissions exist. The sibling common module must verify exact committed sources, execution-manifest identity and a separately committed genuine human authorization bound to that SHA. That authorization is deliberately absent before approval. Its owner check must verify the real parent relation, immutable birth and current process Job membership. The pinned parent supervisor is responsible for proving exact membership in its owned Job through the suspended child handle, setting hard limits before resume and continuously monitoring it. A child `IsProcessInJob(NULL)` check alone proves membership in a Job, not which unnamed Job. The adapter does not claim otherwise and cannot run standalone.

The adapter calls unchanged `headless.memory()` directly. It requires at least 512 MiB physical memory at context startup, 256 MiB during checks, one GiB workspace disk and one GiB actual global system commit headroom. Parent startup commitment must additionally satisfy the separately frozen controller policy, including its Job allowance. Each legacy check validates its supplied physical/disk snapshot and environment, then obtains a fresh actual resource snapshot and rechecks ownership, physical/disk/commit reserves and actual one-thread environment. Supplied commit values, when present, are also checked; the real probe always supplies commit. No public resource-probe, module, guard, bootstrap or owner callback can be substituted. PUM/PRELib exceptions remain inapplicable.

Exactly five module-global aliases named `require_resources` are temporarily replaced: loader.guard, array_contract.validate, joint_engine.adapter, joint_replay.arithmetic and joint_evaluation.evaluation in their frozen namespaces. Fixed source SHA values and exact original function identities are required. The pure original admission function, its globals/constants, every original source byte, ordinary guard/probe functions, imported higher aliases and all other modules remain unchanged. Loader and array imported guard functions continue to execute through their original module globals; provider checks use that same guard module. Adapter V2 and the finite runner reach the original engine gate. No broad project patch or old metadata supervisor floor is changed.

Duplicate/nested contexts, missing/duplicated modules, a previously replaced alias, an active-session replacement and caught guard failures all stop. Every normal, exceptional and partial-install path restores the exact saved callback objects; replacement/restoration failures are retained as integrity errors. The session exposes `.calls` and `.restored`. Before successful context exit, authorization/source identity, owner and live resources are rechecked. The future controller must still enforce lifetime limits, native process/Job caps, descendant accounting and final peak checks.

`session.annotate(payload)` copies a JSON receipt and makes resource provenance honest. An exact reviewed allowlist corrects the four metadata original-gate claims and known `original_resource_guards_unchanged`/resource-changed aliases. It never infers that scientific guards changed: `original_scientific_guards_changed=False` remains false, true is rejected, and unreviewed original-resource/guard fields stop for separate explicit integration. The old resource-gate count is renamed, and an `ORIGINAL_FLOOR` status token becomes `BOUNDED_RESOURCE_CALIBRATION`. Scientific statuses without that operational token, candidate values, IDs and hashes are not altered. Scientific `metadata` and `contract` subtrees are preserved exactly and reject resource-claim fields rather than rewriting hashed content. Annotation adds the manifest/approval/birth identities, an optional separately verified later-stage controller admission SHA, fixed thresholds, measured resource minima and call count. If annotation occurs inside the context, it honestly records restoration as pending; a separate completion receipt must prove `.restored is True`. It never certifies an actual Job cap or peak by itself.

Only metadata execution is currently implemented by the proposed root controller. Array, label, prefit, training, replay and evaluation controllers, admissions and source freezes remain separate prerequisites. In particular, an older label bridge that requires an original-resource flag to remain true will correctly stop on an honestly calibrated receipt; a separately reviewed calibration-aware integration is still needed. This adapter does not conceal that gap or modify scientific parsing, matrices, objectives, configurations, splits, source selection, checkpoints, scores, gates or claims.

Invented tests use private helpers and fresh stand-alone module doubles that are never registered as production modules. They do not enter the public authorized context, manufacture an actual approval record, install a patch on production aliases or invoke Win32/native scientific functions. Their result is proposed-source test evidence only, not validated safety of a lower memory floor.
