# Prefit-only current-runtime provider: draft for review

This new provider supports one source-frozen `fixed_prefit` invocation. It reuses the unchanged reviewed explicit bootstrap, software inventory, source-cache policy and actual loaded-origin proof functions. The only phases are `before_prefit` and `after_prefit`; one bootstrap supplies the same owned NumPy/pandas/SciPy objects in both. Failure poisons the process. No package, original source, array/labels provider or original guard is edited by this provider.

The API is `provide(request_binding, owner_evidence, *, phase, root_start=False)`. The fixed owner verifier is the new execution common module, whose actual source and regular import parents are pinned by preparation. It genuinely checks the original resource authorization, committed execution source, exact source-only controller admission, actual parent/birth/run relation and job membership. It is not a supplied callback or an injectable approval Boolean. The pinned parent supervisor proves exact owned-job assignment and limits before child resume.

The first fresh proof has status `PASS_FRESH_CURRENT_RUNTIME_ORIGINS_FOR_KNOWNCELL_STAGE`, stage `prefit` and phase `before_supplied_input_bridge`. The second proof has phase `after_pool_preparation`. Both bind current PIDs, actual birth, source-only controller admission, static bridge binding, stable admitted array-runtime anchor, software evidence and actual loaded origins. Their SHA is sorted compact finite JSON plus newline, matching bridge V3. Historical V4 origin `dc3e6a1e...` remains separate from fresh proof identity. Old-interpreter bitwise parity is explicitly false.

The hash graph is acyclic: execution source generation, separate source-only controller admission, static bridge binding, runtime request, run admission, actual owned birth and fresh evidence. No current birth/proof hashes occur in precommitted inputs. The runtime preparation pins caller source bytes, while the caller source embeds no runtime-preparation hash literal; its generation manifest supplies that hash at actual admission.

Real fresh checks precede top-level scientific imports and origin/owner actions, using the existing guard module. The approved owned controller alone temporarily binds the exact five resource aliases. Limits stay 512 MiB startup / 256 MiB live physical, 768 MiB process / 896 MiB job, 1,920 MiB startup / 1 GiB live global commit, 1 GiB disk, one worker/thread, 30 minutes and no retry. This provider cannot install that transaction, own a job, open project inputs, prepare pools or authorize an optimizer.

Source preparation actually imports the provider and fixed caller, pins every loaded workspace source plus every regular parent initializer, and rechecks complete software byte maps. Invented tests exercise request order, stable owner identity, one bootstrap, fresh proof ordering, failed-owner/native/resource boundaries and process poisoning. Private mocked edges do not certify actual native execution. No runtime, project input, real probe or job has run during preparation. Final source freeze waits root/interface review and completion of bridge V3.
