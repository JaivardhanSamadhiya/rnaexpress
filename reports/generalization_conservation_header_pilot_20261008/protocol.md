The original schema stage remains technically unavailable: logical track schemas omit `splitTable`, and the public endpoint rejects chromosome-specific SQL table names. This new generation certifies logical output names/types and observes per-track source headers from `getData/track`; it makes no physical SQL table claim.

Before any annotation values are acquired, freeze exactly the first interval for each of the 20 chromosomes in the unchanged 3,003-request roster. Preserve original order, URLs, assembly, track order, coordinates and output cap. No pilot is chosen or replaced based on returned scores or coverage. Empty arrays may admit well-formed headers and represent missing values. Invalid, failed or capped pilots leave that chromosome unavailable without retry, substitution or alternate interval.

Require complete HTTP 200, exact trusted URLs, strict duplicate-preserving ordered JSON parsing, exact track types from the preserved logical schemas, raw source calendar strings and positive integer timestamps, bound arrays, exact coordinates, no overlaps, finite values and phastCons in [0,1]. Reuse the unchanged reviewed value parser, explicitly sharing its implementation rather than claiming independent parsing. First-creation response receipt hashes bind raw bytes. Public free source: [UCSC API](https://genome.ucsc.edu/goldenPath/help/api.html); [terms](https://genome.ucsc.edu/license/).

These 20 requests retrieve annotation values, so this stage is explicitly value-bearing, not metadata-only. It reads no localization outcomes, fits no models and constructs no features. After all 20 outcomes are preserved and reviewed, a separate committed freeze is required for the other 2,983 exact requests. It must bind all pilot bodies and the 40 observed chromosome/track header signatures, reuse the pilot bodies, and mark later header drift unavailable without updating the reference. No remaining request is authorized by this pilot manifest.

Source-reported matching headers do not certify a single atomic provider snapshot, physical SQL identity, a live binary version, original full-precision scores or biological relevance. Original whole-parent missingness and all 26,258 original rows/menus remain mandatory in any later feature stage; no failed parents may be dropped.
