# Supplied-byte simple102 array contract, no project admission

Completed 23 October 2026 in the additive namespace begun on22 October. The three original partial sources remain byte-for-byte unchanged. New sources complete a pure supplied-byte validator and invented standard-library checks. No project NPZ, CORE table, label, metadata receipt, model, prediction or source-input manifest is opened. No NumPy, pandas, SciPy, encoder or native scientific runtime is imported or called. No native resource probe, actual project admission or fit runs. Preparation reads only source text and this namespace's own invented-test receipt.

## Input contracts without an actual alias claim

The future main function takes NPZ bytes, metadata records, original creation-receipt bytes and original metadata-receipt bytes supplied by a separate caller. Every byte object must match an explicit expected SHA from that future caller. It does not locate or open a path, infer a pin from supplied content, retrieve an old manifest or certify that any supplied bytes belong to a project alias/Git commit. No path loader or automatic execution CLI is implemented. Input alias strings retained in the original partial spec are declarations only and are never followed by preparation or tests.

The real entrypoint fixes shape13781x102 and invokes the frozen full metadata contract, including all original rows,187 components, exact paired/unmatched menus and both-cell inner/outer coverage. Separately, row IDs must match the caller's independent expected row-order hash and BOTH supplied original receipts. The creation receipt must retain statusPASS, exact simple width/count and its original no-outcome/no-new-feature/no-fit flags; the metadata receipt must retain exact count/component identity and original-allele/no-label/no-fit flags. All supplied JSON rejects duplicate keys and is size-bounded. A future caller must bind these exact original receipt hashes and the NPZ hash to the original committed freeze; this module does not establish that lineage merely from a supplied PASS string.

The generic low-level shape argument and tiny receipt fixtures exist for invented structural/identity tests. They do not weaken the public main entrypoint's fixed13781x102 shape or full metadata checks. No tiny fixture can receive a real full-shape or project admission certificate.

## Bounded ZIP/NPY inspection before deferred NumPy

Compressed NPZ bytes are limited to32MiB. Expanded NPY bytes are limited to11,300,000 decimal bytes, below11.3MiB; the fixed scalar payload itself occupies11,245,296 bytes. Headers are limited to4096 bytes. The supplied expected SHA is checked. The archive must contain exactly one unencrypted, non-directory `features.npy`, with no duplicate/unexpected member, prefix, comment, trailing data, central-directory gap or additional local payload. ZIP stored/deflate methods only are accepted. A complete bounded deflate stream, local/central agreement, size and CRC are verified. Local ZIP64 size fields from the original seekable NumPy writer are supported; multi-disk, data-descriptor and unsupported flag conventions are rejected rather than silently substituted.

The NPY magic/version/header are parsed without NumPy or pickle. Versions1.0/2.0, an exact literal three-key header, scalar non-object float64, a real boolean storage-order flag and exact positive two-dimensional fixed shape are required. Duplicate header keys, executable expressions, object/structured/float32 descriptors, malformed/truncated/oversized headers and extra/truncated/overflow scalar data fail. Byte length must be exact. Every scalar is independently checked finite using standard-library binary64 decoding. Endian and C/Fortran storage order are preserved, not guessed or normalized by a feature reconstruction.

For every supplied identical `(parent_sequence,mutant_sequence)` group represented in both cells, feature rows must have EXACT equal float64 bytes. No tolerance, rank matching, intersection trimming or zero filling is used. Signed-zero or one-bit differences fail. Single-cell-only groups remain retained and are not falsely called cross-cell matches.

## Deferred load and original numerical convention

The caller must already have accepted actual current-Python NumPy origins and supply their receipt SHA plus the module object. This module does not import that module or establish external runtime acceptance from a boolean. It requires a real future resource-probe callback and one-thread environment, with the original at-least3GiB available physical RAM and at-least1GiB workspace disk before supplied-data validation and immediately before the deferred numerical call. The PUM exception does not apply. Current tests use invented callbacks only; no live resource measurement is claimed.

Only after structural, finite-value, metadata/order/count and source-byte checks does the code call `np.load(BytesIO(raw),allow_pickle=False)`, require sole key `features`, and use the exact original `archive['features'].astype(float)` convention. It checks native non-object float64, shape and NumPy finiteness. All logical C-order output bytes are independently compared to the original scalar payload after byte-only endian/storage-order conversion. This verifies actual deferred load/cast bit preservation without a rounding tolerance or altered choice semantics. Cross-cell exact-allele byte equality is checked again on the cast bytes.

The function returns the matrix and `VALIDATED_SUPPLIED_ARRAY_BYTES_NOT_PROJECT_ADMISSION`. It never returns the loader's project-array admission status or writes an admission file. The result explicitly says that project aliases, Git commit lineage and external runtime acceptance are not certified here. A future independently reviewed project wrapper must perform guarded payload acquisition, exact original pin/commit and metadata-bundle binding, actual accepted runtime/resource proof and immutable admission writing before the FIT-label stage can use a project-array certificate. That wrapper is not implemented by this increment.

It is not a real NumPy compatibility certificate or full-shape positive validation.

Readiness binds current own sources, unchanged partial-file SHA values, report/attributes, invented-test receipt and the relevant frozen reference SOURCE files.
