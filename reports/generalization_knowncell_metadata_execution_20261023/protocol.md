# Original-floor metadata admission

This stage executes only the already reviewed selective metadata loader. Before
execution the root must review and commit its exact admission and source
manifest. It verifies the existing CORE bytes, retains only the ten declared
Mikl metadata fields, reconstructs all 13,781 rows, 187 components, 2,408 exact
paired menus and both-cell inherited-fold masks, and checks the old paired and
unmatched inventories. The parser traverses all raw CSV tokens, including unused
effect tokens; it neither converts nor retains numerical effects. It does not
open a feature array, import a numerical package, fit a model or admit other
studies. Metadata include the already exposed Mikl parent/mutant sequences.

All original floors remain: at least three GiB available physical RAM and one
GiB workspace disk before each original guarded read, with four numerical thread
variables fixed to one. The controller additionally reserves one GiB system
commit, monitors the original RAM/disk floors, and stops its own job after five
minutes. The unchanged Windows job caps are 768 MiB per process, 896 MiB total
and two active processes: the sole metadata worker and its pinned direct Git
helper. No other worker's guard is altered. PUM and PRELib exceptions do not
apply. No dependency, download, purchase or scheduling is required.

A startup floor failure records a blocked attempt without starting a worker or
opening a project payload. Every output is exclusive and durable; failed and
partial outputs are retained. There is no automatic retry or resume. A completed
metadata bundle must be independently checked and committed before a separate
array or numerical-label admission. This stage never authorizes fitting.
