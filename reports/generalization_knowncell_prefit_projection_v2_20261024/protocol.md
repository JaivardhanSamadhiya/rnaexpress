# Stable campaign identity and separately verified current stage

V1 remains unchanged, unexecuted on actual project inputs and source-frozen at `b75fe84445b9407154de1c26c7ed60b85f2d41852ff29c12803d80fcafeed355`. Root identified a concrete later-stage compatibility defect: V1 put the freshly verified current owner/context hash into `plan.identity()`. The unchanged supplied-campaign replay requires that identity to exactly equal the saved campaign birth/completion. An honestly new replay owner necessarily changes current operational provenance. Reusing the fit owner as current would be false, and changing the recorded campaign identity would fail replay.

This V2 library delegates all unchanged V1 raw-byte, exact-commit, truthful-true, one-field-view, scientific-validator and mandatory context-verifier checks, then returns a V2 subclass. `identity()` removes only V1's current owner receipt and caller-current-context hash from the compatibility descriptor. It marks the stable identity as version 2 and makes the separation explicit. Stable identity still binds actual prefit raw SHA/commit/runtime, raw/view canonical hashes, the sole flag projection, stable root-prefit-admission path/commit/hash, prefit owner SHA, projection source manifest, policy/auth/scope and input-admission bindings. All added prefit provenance remains unchanged. V1's source and identity semantics are not patched.

`operational_context()` separately returns the actual supplied current owner receipt hash, current-context raw hash, detached full verified context and the stable campaign identity hash. It performs no new resource/native/owner check itself. It records the snapshot required and verified by the mandatory fixed real controller callback at binding. Future owned fit and replay stages must each supply their own newly and actually verified current context. Both must retain the same stable committed root prefit-compatibility admission; their separate stage execution admissions and owner evidence remain outside campaign identity. Controllers must persist the operational descriptor in their owned-stage receipts, never insert it into the old immutable campaign identity or mislabel fit-time ownership as current.

The API remains `bind_calibrated_plan(prefit_raw, admission_raw, context_raw, *, committed_reader, verify_root_context)`. The future root controller must pin and independently review both real verification callables for each stage. No default actual verifier, resource alias, monkeypatch, reader, runtime import, authority grant or worker is supplied here. Original stage/input/runtime guards, live-owner proofs and checkpoint integrity checks remain mandatory external obligations. `rebind_prepared` delegates V1's exact old-key, extra-provenance and pool-binding checks while requiring the stable V2 type; metadata/pool object identities remain unchanged.

Invented tests reproduce the V1 blocker, demonstrate identical V2 campaign identities across two independently supplied current owners and different current-proof encodings, require verification for both contexts, preserve stable identity sensitivity to changed actual prefit/root admission, and exercise the original writer plus the original replay's exact birth/completion equality checks. The replay test uses empty invented record envelopes and deliberately raises before the first pool or model is examined. It is not a model replay, a 63-checkpoint arithmetic verification or an execution proof. Temporary writes contain an invented campaign birth only. No project prefit, metadata, array, labels, native package, resource probe, actual owner context, optimizer or model is loaded or created during preparation.
